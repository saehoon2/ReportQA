# 평가 가이드

ReportQA의 버전별(v0, v1, v2 …) 성능을 **같은 기준**으로 재기 위한 규칙입니다.
테스트셋을 만들기 전에 규칙을 먼저 정하고, 평가 중에는 바꾸지 않습니다.

---

## 1. 테스트셋

### 1-1. 파일
- 위치: `eval/testset.csv` (GitHub에 올림)
- 인코딩: UTF-8, 첫 줄은 열 이름
- 열 이름과 값은 코드에서 쓰기 쉽게 영문으로, 질문·정답은 한글로 적습니다.

| 열 | 설명 | 예시 |
|---|---|---|
| `id` | 문항 번호. 유형 첫 글자 + 3자리 | `T001`, `B001`, `C001`, `U001` |
| `type` | 유형: `text` / `table` / `chart` / `unknown` | `table` |
| `chart_kind` | 차트일 때만: `vector`(숫자가 글자로 추출됨) / `image`(그림이라 글자 없음) | `image` |
| `doc_id` | 정답이 있는 문서 (모름 문항은 비움) | `D02` |
| `question` | 질문 | 2025년 4분기 음악 산업 매출액은? |
| `answer` | 정답 (단위 포함, 모름 문항은 `모름`) | 4,056,713백만 원 |
| `answer_pages` | 정답이 있는 쪽. 여러 쪽이면 `;`로 구분 (모름 문항은 비움) | `45` 또는 `1;17` |
| `note` | 근거 위치, 주의할 점 | 표 1-1 |

> `id` 첫 글자: T=텍스트(Text), B=표(taBle, T와 겹치지 않게), C=차트(Chart), U=모름(Unknown)

### 1-2. 문항 배분 (110문항)

| 유형 | 합계 | D01 | D02 | D03 |
|---|---|---|---|---|
| 텍스트 | 40 | 13 | 14 | 13 |
| 표 | 30 | 10 | 14 | 6 |
| 차트 | 30 | 12 (image) | 0 | 18 (vector) |
| 모름 | 10 | - | - | - |

- D02의 차트(그림 1-1~1-5)는 모두 바로 뒤 표(표 1-1~1-5)의 숫자를 그린 것이라 "차트에만 있는 값"이 없어 차트 문항을 만들지 않았습니다.
- 차트 문항은 과거 연도 값이 차트에만 있는 **추이 차트**에서 만들었습니다. (D01: 3개 차트, D03: 16개 차트)
- D01 이미지 차트는 3개 차트에 몰려 있어 한계가 있습니다. 문서를 추가할 때 이미지 차트가 많은 문서로 보강합니다.

### 1-3. 질문 작성 규칙
1. **답이 하나로 정해져야 합니다.** 연도·월·대상·단위를 질문에 명시합니다.
   - ❌ "고용률은?" → ✅ "2026년 5월 20~24세 고용률은?"
2. **정답 쪽에서 직접 확인할 수 있어야 합니다.** 여러 쪽에 같은 답이 있으면 모두 `answer_pages`에 적습니다.
3. **유형은 "정답이 어디에 있는가"로 정합니다.**
   - 텍스트: 본문 문장에 답이 있음
   - 표: 표 안에만 답이 있음 (본문에도 있으면 텍스트로 분류)
   - 차트: 차트 안에만 답이 있음 (본문에도 있으면 텍스트로 분류)
4. **모름 문항은 그럴듯하지만 문서에 없어야 합니다.** 미래 전망, 다른 나라, 다루지 않은 대상 등
5. 계산이 필요한 질문(두 숫자의 차이 등)은 v0~v2 평가 범위에서 제외합니다.

### 1-4. 작성·검토 절차
1. Claude가 원문(쪽 그림과 추출 글자)을 보고 문서 단위로 초안 작성
2. 사용자가 **전 문항 검토**: 질문이 자연스러운지, 정답과 쪽이 맞는지 PDF로 확인
3. 수정 사항 반영 후 커밋
4. 순서: D01 → D02 → D03 → 모름 10문항

### 1-5. 테스트셋 변경
- 평가를 시작한 뒤 문항을 고치면, **이미 평가한 모든 버전을 다시 평가**합니다. (같은 시험지로 비교해야 하므로)
- 변경 내용은 이 문서의 변경 이력에 남깁니다.

## 2. 채점

### 2-1. 검색 점수: 쪽 단위 Recall@5
> 검색된 상위 5개 청크의 쪽 중에 `answer_pages`가 **하나라도** 있으면 성공

- 예: 정답 쪽 `45`, 검색된 쪽 `[46, 44, 45, 50, 15]` → 성공
- 같은 문서의 같은 쪽일 때만 인정합니다. (`D02 p.45`와 `D03 p.45`는 다름)
- 모름 문항은 정답 쪽이 없으므로 Recall 계산에서 제외합니다. (100문항 기준)

### 2-2. 답변 점수: LLM 채점
채점 모델(`JUDGE_MODEL`)이 RAG의 답변과 정답을 비교해 아래 4가지 중 하나로 판정합니다.

| 판정 | 조건 |
|---|---|
| `correct` | 정답과 같은 내용 (표현·반올림 차이는 허용. 예: 161조 4,839억 원 ≈ 약 161.5조 원) |
| `wrong` | 숫자·대상이 틀림, 또는 정답의 핵심이 빠짐 |
| `refused` | 답이 있는 질문에 "모름" |
| `hallucinated` | 모름 문항에 "모름"이 아닌 답을 함 |

- 모름 문항에 "모름"으로 답하면 `correct`입니다.
- **정답률** = `correct` 수 / 전체 문항 수
- **환각률** = `hallucinated` 수 / 모름 문항 수

### 2-3. 채점기 검증 (처음 한 번)
- v0 평가 후, 채점 결과 중 **20문항을 사람이 직접 채점**해 LLM 판정과 비교합니다.
- 일치율이 90% 이상이면 채점기를 그대로 씁니다. 낮으면 채점 프롬프트를 고치고 다시 검증합니다.

- 평가할 때마다 사용한 모델 이름, `CHUNK_SIZE`, `TOP_K`를 함께 기록합니다. (설정이 다르면 비교할 수 없으므로)
